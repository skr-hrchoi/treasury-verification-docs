# 1. 개요 — 무엇을 하는 장치인가

## 1.1 한 줄 설명

자금관리포털 화면에 찍히는 숫자가 원천 자료(사내 자금일보 시스템 SamsApi)와 정말로 같은지를,
사람 대신 매일 아침 자동으로 대조해 보고 알려주는 감시 장치입니다.

!!! quote "비유하자면"
    회계 담당자가 매일 아침 통장 잔고와 장부를 한 줄씩 맞춰 보는 일을 프로그램이 대신합니다.
    다른 점은 두 가지입니다. 사람은 보통 '오늘 자'만 보지만 이 프로그램은 **과거 기준일 전체
    (회사별 360건)** 를 매번 다시 훑고, 사람 눈에는 안 보이는 **1원 단위**까지 봅니다.

## 1.2 무엇을 지켜보는가

포털의 숫자는 원천에서 화면까지 여러 단계를 거칩니다. 단계마다 어긋날 수 있는 지점이 있고,
이 시스템은 그 지점을 층별로 나눠 짚습니다.

```
[사내 SamsApi]  →  [수집·가공]  →  [Supabase 저장]  →  [화면 계산]  →  [사람이 보는 숫자]
       │                  │                │                 │
       └── ① 원천과 ──────┴── ② 저장된 값 ─┴── ③ 화면에 ─────┘
           같은가?            끼리 앞뒤가       찍히는 값이
                              맞는가?           맞는가?
```

| 검사하는 층 | 확인하는 질문 | 해당 검사 |
| --- | --- | --- |
| ① 원천 대비 | 포털이 들고 있는 값이 사내 자금일보와 같은가 | 총 보유현금 · 시재 · 채권 매입금액 · 채권 평가단가 · 보유목록 |
| ② 저장 데이터 내부 | 저장된 값끼리, 정의상 반드시 맞아야 할 합이 맞는가 | 지사별 통장합계 · 현금 통화별 합계 · 주식 요약↔종목합 |
| ③ 화면 계산 | 화면 코드를 실제로 돌렸을 때 나오는 숫자가 맞는가 | 현금 화면 정합성 (총보유현금 · 통화별 · 계열사별 · 추이그래프) |

### 사람이 눈으로 하기 어려운 이유

- 같은 금액이 화면 **네 곳**(상단 요약 · 통화별 표 · 계열사별 표 · 추이 그래프)에서 각각 계산돼 찍힙니다.
- **오늘 자만 봐서는 부족합니다.** 과거 기준일로 넘겼을 때만 어긋나는 종류의 오류가 실제로 있었습니다
  (2026-08-21 장애 — [변경 이력](../changelog.md) 참조).
- 화면은 **억 단위로 반올림**해 보여주므로, 원 단위 오차는 화면만 봐서는 보이지 않습니다.
- 3사 × 여러 통화 × 여러 자산군의 조합이라 손으로 대조할 분량이 아닙니다.

| 구분 | 내용 |
| --- | --- |
| 검사 대상 | 자금관리포털이 보여주는 현금 · 채권 · 주식 숫자 |
| 비교 기준(원천) | 사내 자금일보 시스템 SamsApi (사내망 전용 · 접속 주소는 사내 문서 참조) |
| 대상 회사 | 장금상선(SNKO) · 흥아라인(HALK) · 한성라인(HSLI) + 계열 합산 |
| 검사 항목 수 | 36개 (2026-09-10 09:10 실행 기준, [늘고 주는 값](checks.md#36)) |
| 자동 실행 | 평일(월~금) 09:10 전체 검증 / 평일 매시 05분 현금 재검증 점검 |
| 결과 보관 | `reports\` 폴더에 일자별 JSON, `snapshots\` 폴더에 그날의 원자료 사본 |
| 결과 확인 | `reports\dashboard.html` — 달력형 대시보드, 인터넷 없이 열림 |
| 자동 경보 | 현금 화면 팝업 — 자동배포가 이상을 찾으면 화면에 창을 띄움 |
| 실행 환경 | Python 3.11+ · Git Bash · Windows 작업 스케줄러 (이 PC에서만 돎) |

!!! warning "검증기는 읽기만 합니다"
    검증기는 포털 데이터를 고치지 않습니다. 무인으로 도는 프로그램이라
    삭제 · 배포 · 외부 전송 같은 동작은 설계 단계에서 금지되어 있습니다.
