# 2. 동작 원리

## 2.1 검증 한 번에 벌어지는 일

평일 09:10, 작업 스케줄러가 `run_verification.cmd` 를 실행하면 아래가 순서대로 돕니다.
실제 실행 순서는 `run_verification.sh` 에 적힌 그대로이며,
2026-09-10 실행은 처음부터 끝까지 **35초**가 걸렸습니다.

```text
① compare.py         저장 데이터 내부 정합성 (지사합 · 통화별합)      → 6개
② source_compare.py  현금 총계 · 시재를 원천(SamsApi)과 대조          → 6개
③ bond_verify.py     채권 매입금액 · 평가단가 · 보유목록 원천 대조    → 12개
④ stock_verify.py    주식 요약↔종목합 · 내부정합성 · 현재가 교차검증  → 5개
⑤ cash_screen.py     '화면에 찍히는 숫자'를 전 기준일에 걸쳐 대조      → 7개
                                                              ─────────
⑥ merge_results.py   결과를 합쳐 reports/<일시>.json + latest.json      36개
⑦ recheck.py         지난 14일치 '검증불가' 항목을 다시 조회해 정정
⑧ build_dashboard.py 달력형 대시보드 reports/dashboard.html 다시 그림
```

①~⑤는 각각 그 시점의 원천 응답과 포털 값을 `snapshots\<일시>\` 폴더에 그대로 저장합니다.
나중에 '그날 왜 그렇게 판정했나'를 되짚기 위해서입니다.

## 2.2 다섯 가지 설계 원칙

이 시스템이 왜 이런 모양인지를 설명하는 규칙입니다. 기능을 더할 때도 이 다섯 가지는 지킵니다.

| 원칙 | 내용 | 왜 그렇게 하나 |
| --- | --- | --- |
| **① 판정은 코드, 해석은 AI** | 숫자가 맞고 틀리고는 Python 스크립트가 판정한다. AI는 그 결과를 읽고 원인을 추정하고 보고서를 쓴다. | 검증 결과는 언제 돌려도 똑같아야 한다. AI가 직접 숫자를 비교하면 같은 자료로도 답이 달라질 수 있다. |
| **② 기대값은 독립 재계산** | 검증기는 포털·수집기의 계산 코드를 가져다 쓰지 않는다. 원천 자료에서 처음부터 다시 계산한다. | 같은 코드를 양쪽에서 쓰면 버그도 양쪽에 똑같이 생겨 '틀린 값끼리 일치'하게 된다. |
| **③ 검증불가 ≠ 검증실패** | 사내망이 안 되거나 API가 거절하면 실패가 아니라 '검증불가'로 분류한다. | 값이 틀린 것과 물어보지 못한 것은 다른 상황이다. 섞으면 진짜 실패를 못 알아본다. |
| **④ 모든 검증은 스냅샷 보관** | 판정에 쓴 원천 응답과 포털 값을 `snapshots\` 에 그대로 저장한다. | 나중에 판정 근거를 되짚을 수 있고, 검증불가 항목을 사후에 되살릴 수 있다. |
| **⑤ 지표는 설정으로 선언** | 검사 대상·허용 오차는 `config\metrics.yaml` 에 적는다. | 지표를 늘릴 때마다 프로그램을 고치면 고칠수록 위험해진다. |

## 2.3 판정 등급과 심각도

### 판정 등급 — 각 항목이 받는 성적

| 판정 | 대시보드 표시 | 의미 | 해야 할 일 |
| --- | --- | --- | --- |
| `PASS` | <span class="verdict pass">통과</span> (초록 ✓) | 기대값과 실측값이 허용 오차 안에서 일치 | 없음 |
| `FAIL` | <span class="verdict fail">실패</span> (빨강 ✕ / 주황 !) | 값이 어긋났다. 포털 숫자가 틀렸을 가능성 | [6.1절](troubleshoot.md#61-fail) 즉시 수행 |
| `UNVERIFIABLE` | <span class="verdict unver">검증불가</span> (노랑 ?) | 틀린 게 아니라 '물어보지 못했다'. 대개 사내 API 속도제한(429) | 대개 다음 실행 때 자동 정정. 며칠 이어지면 [6.2절](troubleshoot.md#62-unverifiable) |

### 심각도 — 그 항목이 얼마나 중요한가

| 심각도 | 해당 항목 | 판단 기준 |
| --- | --- | --- |
| `CRITICAL` | 금액이 원천과 어긋나는 것 — 현금 총계, 현금 화면 정합성, 채권 매입금액·평가단가, 주식 요약↔종목합, 내부 정합성 | 잘못된 금액이 경영 보고에 그대로 들어갈 수 있음 |
| `WARNING` | 채권 보유목록 증감, 현금(시재) 대조, 주식 현재가 교차검증 | 알아야 하지만 즉시 오보로 이어지지는 않음 |
| `INFO` | 참고 사항 | 기록용 |

!!! info "그날 하루의 종합 판정"
    CRITICAL 실패가 1건이라도 있으면 **「위험」**, 그 밖의 실패가 있으면 **「실패」**,
    검증불가만 있으면 **「주의」**, 전부 통과면 **「정상」** 입니다.
