# 4. 자동 실행 일정

## 4.1 등록된 예약 작업

이 PC의 Windows 작업 스케줄러에 실제로 등록되어 도는 것은 아래와 같습니다.
**모두 이 PC가 켜져 있고 로그인된 상태에서만** 돕니다.

| 언제 | 무엇이 도는가 | 작업 스케줄러 이름 | 실행하는 것 |
| --- | --- | --- | --- |
| 평일(월~금)<br>**09:10** | 전체 검증 36개 항목 | `자금관리포털_대시보드검증` | `검증시스템\run_verification.cmd auto` |
| 평일(월~금)<br>**매시 05분** | 자동배포 — 이때 ① 현금 화면 정합성 점검 ② 현금 값이 바뀌었으면 현금 검사만 재실행 | `TreasuryDashboard_AutoDeploy` | `자금관리포털\홈페이지배포\auto-deploy.ps1` |
| 평일<br>09·12·15·17:30<br>17:50·18·18:30·21시 | 원천 데이터 수집 (SamsApi 자금일보 → 포털 데이터) | `SinokorTreasuryDashboard`<br>(로그온 시 상주하는 수집서버 안의 일정) | `데이터수집서버\server.js` |
| 매 검증 실행 시 | 사후 재검증 — 지난 14일치의 '검증불가' 항목을 다시 조회해 정정 | (별도 등록 없음) | `run_verification.sh` 안에 포함 |

!!! warning "PC가 꺼져 있으면 그날은 건너뜁니다"
    작업 스케줄러는 PC가 꺼져 있거나 로그인되어 있지 않으면 실행하지 않고,
    **나중에 몰아서 돌려주지도 않습니다.**
    그날 검증이 돌았는지 확인하는 방법은 [6.3절](troubleshoot.md#63)에 있습니다.

## 4.2 수집과 검증을 10분 떼어 놓는 이유

사내 SamsApi 에는 속도제한이 걸려 있습니다. 짧은 시간에 같은 API 키로 호출이 몰리면 서버가
**HTTP 429**(요청이 너무 잦습니다)로 거절합니다. 수집기와 검증기는 같은 키를 쓰므로,
두 프로그램이 같은 시각에 돌면 서로의 호출을 잡아먹습니다.

1. **실행 시각 분리** — 수집 09:00, 검증 09:10. 수집이 끝난 뒤 검증이 시작됩니다.
2. **검증기 자체의 완충** — 호출 사이에 간격을 두고, 거절당하면 잠시 뒤 다시 시도합니다
   (`checks/common/samsapi.py`).

그래도 거절당하면 그 항목은 실패가 아니라 **검증불가**가 되고, [4.4절](#44)의 사후 재검증이 이어받습니다.

## 4.3 현금만 따로 다시 보는 장치 {: #43 }

전체 검증은 하루 한 번(09:10)뿐인데, **현금 데이터는 낮과 저녁에 회사별로 따로 들어옵니다.**
그래서 09:10에는 3사가 모두 전일 이월이라 멀쩡했다가, 오후에 한 회사만 당일 마감이 끝나면
계열 화면이 3사 합과 어긋날 수 있습니다.
이를 잡기 위해 자동배포가 매시 05분에 `cash_recheck.py` 를 불러 아래 순서로 처리합니다.

1. **현금 지문**(잔액·환율·지사합계·은행명세·화면코드 해시)을 직전과 비교합니다.
2. 바뀐 게 없으면 아무것도 하지 않고 끝냅니다. 하루 스무 번 넘게 불려도 헛돌지 않습니다.
3. 바뀌었으면 **현금 검사 7개만** 다시 돌려 그날 리포트와 대시보드를 갱신합니다.

!!! example "실제 하루 (2026-09-09)"
    22번 호출됐고, 그중 **15번은 '변경 없음'으로 즉시 종료**,
    값이 실제로 바뀐 **7번**(08:47 · 09:05 · 12:05 · 15:05 · 18:05 · 19:05 · 21:05)만 재계산했습니다.
    기록은 `logs\cash-recheck.log` 에 남습니다.

## 4.4 사후 재검증 — 물음표로 남은 항목을 되살리는 장치 {: #44 }

검증불가로 남은 항목은 값이 틀린 것이 아니라 '그 순간 물어보지 못한' 것입니다.
그대로 두면 그날 기록이 영원히 물음표로 남으므로, 매 검증 실행 때마다 **지난 14일치** 리포트의
검증불가 항목을 훑어 지금이라면 확인 가능한 것을 정정합니다.

### 되살릴 수 있는 구조적 이유

- 검증기는 원천을 부르기 **전에** 포털 쪽 값을 먼저 스냅샷으로 저장합니다(원칙 ④).
  원천이 거절당해도 포털 쪽 증거는 남아 있습니다.
- SamsApi 는 **과거일 조회**를 지원합니다.
  → 「그날 저장된 포털 값」 vs 「그날 기준일로 지금 다시 부른 원천」 = 그날의 검증을 그대로 재현합니다.

### 정정할 때 지키는 세 가지

1. 포털 값은 **그때 저장된 스냅샷**을 씁니다. 지금 화면값을 쓰면 그날의 검증이 아니게 됩니다.
2. 원천은 **그날 기준일로** 조회합니다.
3. 비교 로직은 당일 검증과 **똑같은 함수**를 씁니다.

정정된 항목은 숨기지 않습니다. 원래 판정과 정정 시각이 함께 기록되고, 대시보드에는
「↺ 사후 재검증 (날짜)」 꼬리표가 붙습니다.

되살릴 수 있는 항목은 **채권 3종 · 총 보유현금 · 시재금**이며,
주식 현재가 교차검증과 현금 화면 검사는 포털 쪽 원자료가 스냅샷에 남지 않아 되살릴 수 없고
사유를 적고 그대로 둡니다.

## 4.5 공휴일에도 실행된다 (주의) {: #45 }

!!! danger "공휴일이라고 검증이 쉬지는 않습니다"
    예약작업은 '월~금'으로만 등록돼 있고, Windows 작업 스케줄러에는 **공휴일이라는 개념 자체가 없습니다.**
    실행 파일(`run_verification.cmd` / `.sh`)에도 공휴일을 건너뛰는 분기가 없습니다.

    - 평일에 걸린 공휴일(예: 2026-09-24 목 · 09-25 금 추석)에도 PC가 켜져 있으면 검증은 그대로 돕니다.
    - 그날 원천이 전 영업일 값에 머물러 있으면 전 영업일 기준으로 대조한 결과가 남습니다.
    - 반대로 PC를 끄고 쉬면 그날 칸은 비어 있게 되며, 그것도 정상입니다.

참고로 대시보드 달력은 일요일과 공휴일의 날짜를 붉게 칠하고 공휴일 이름(예: 추석)을 함께 보여줍니다.
이 공휴일 목록은 `checks/build_dashboard.py` 안에 연도별로 적어 둔 것이라
**해가 바뀌면 갱신해야 합니다.**
