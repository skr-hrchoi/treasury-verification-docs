# 설계 원칙과 개발 규칙

원본은 저장소 루트의 `CLAUDE.md` 입니다. 이 페이지는 그 규칙을 사람이 읽기 좋게 옮긴 것이며,
**둘이 어긋나면 `CLAUDE.md` 가 기준**입니다.

## 다섯 가지 설계 원칙

### ① 결정적 검증 + AI 분석 분리

- 수치 비교·보안 스캔·무결성 체크는 `checks/` 아래 **Python 스크립트**가 수행한다.
- AI 는 결과 JSON 을 해석·분석·리포트하는 역할만 한다.
- **AI 가 직접 숫자를 비교해 통과/실패를 판정하지 않는다.**

> 검증 결과는 언제 돌려도 똑같아야 합니다. 판정에 모델이 끼면 같은 자료로도 답이 달라집니다.

### ② 기대값 독립 재구현

- 수치 검증의 기준(Source of Truth)은 외부 API 다.
- 검증 스크립트는 **대시보드·수집기 코드를 재사용하지 말고**, 원시 데이터로부터 기대값을 독립 재계산한다.

> 같은 코드를 양쪽에서 쓰면 버그도 같이 생겨 '틀린 값끼리 일치'합니다.
> 그래서 `checks/common/samsapi.py` 는 수집기 `lib/samsapi.js` 와 별개로 구현돼 있고,
> 총 보유현금도 원천의 합계행(TOT)을 그대로 믿지 않고 통화별 행을 직접 합산해 재구성합니다.

### ③ 검증 불가 ≠ 검증 실패

- 외부 API 장애·타임아웃 시 결과는 `UNVERIFIABLE`. **`FAIL` 로 처리하지 않는다.**

### ④ 모든 검증은 스냅샷 기반

- 검증 시점의 외부 API 응답과 대시보드 추출값을 `snapshots/` 에 저장한다.
- 파일명 규칙: `snapshots/{YYYY-MM-DD_HHMM}/{metric_id}_{source|dashboard}.json`

### ⑤ 선언적 지표 정의

- 검증 대상 지표는 `config/metrics.yaml` 에 선언한다.
- 새 지표 추가 시 **코드 수정 없이** yaml 에 항목만 추가하면 동작해야 한다.

## 개발 규칙

| 항목 | 규칙 |
| --- | --- |
| 언어 | Python 3.11+, 표준 라이브러리 우선. 외부 의존성은 `requirements.txt` 에 고정 |
| 시간 | 내부 계산은 UTC, 표시·리포트는 Asia/Seoul. **naive datetime 금지** |
| 수치 비교 | 지표별 tolerance 는 `metrics.yaml` 에서 읽는다. **코드에 하드코딩 금지** |
| 시크릿 | API 키는 환경변수 또는 `.env`(git 제외)로만. 코드·yaml 에 직접 기입 금지 |
| 단독 실행 | 각 검사 스크립트는 혼자서도 돌아가야 한다 (`py checks/metrics/compare.py --metric <id>`) |
| 한국어 | 리포트·주석·로그 메시지는 한국어로 작성 |

## 무인 실행이라서 금지된 것

이 프로그램은 사람이 보지 않는 시각에 자동으로 돕니다. 그래서:

- **파괴적 명령 금지** — 삭제 · 배포 · 외부 전송
- 검증기는 **읽기 전용**. 포털 데이터를 고치지 않는다
- 외부로 나가는 통신은 원천 조회(사내망)와 주식 현재가 교차검증(야후)뿐

## 바꾸면 안 되는 것 (실무 규칙)

- 검증기가 포털·수집기의 계산 코드를 가져다 쓰는 변경 — 원칙 ②
- AI 가 직접 판정하게 하는 변경 — 원칙 ①
- 사내망 오류를 `FAIL` 로 처리하는 변경 — 원칙 ③
- 새 화면 지표를 **'저장 데이터만 보기'** 또는 **'최신 1행만 보기'** 로 만드는 것
  → 2026-08-21 장애가 정확히 이 두 함정에서 나왔습니다. [구조와 데이터 흐름](architecture.md) 참조
