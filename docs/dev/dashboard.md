# 대시보드 생성기 (`build_dashboard.py`)

`reports/*.json` 을 읽어 **자체 완결형 HTML 한 파일**을 만듭니다.

```bat
py checks\build_dashboard.py --reports-dir reports --out reports\dashboard.html
```

## 설계 조건

| 조건 | 이유 |
| --- | --- |
| 외부 CDN·폰트·스크립트를 쓰지 않는다 | 인터넷 없이 열려야 하고, **재무 데이터가 밖으로 나가면 안 된다** |
| 데이터를 HTML 안에 박아 넣는다 | `<script id="data" type="application/json">` 한 덩어리 |
| 최근 실행만 담는다 | `MAX_RUNS = 200` — 파일 크기 상한 (현재 약 842KB) |

## 만들어지는 구조

```
상단  : 제목 + 「생성 <날짜 시각>」
        └ 일자별 종합 검증 결과 (달력) — 날짜 클릭 시 하단 갱신
하단  : #detail
        ├ 종합 판정 배너 (위험/실패/주의/정상)
        ├ 대상일 (자산 종류별 대표 as_of 최빈값)
        ├ 요약 숫자 (전체/통과/실패/검증불가)
        ├ 회귀 추적 (직전 일자 대비 신규 실패·복구)
        ├ 검증 상세 표 (회사별 구분선 + 지표/분류/상태/기대값/실측값/갭/설명)
        └ 정합성 갭 추세 (지표별 스파크라인)
```

## 종합 판정 규칙

```javascript
if (CRITICAL 실패 > 0)      → '위험'   (critical, 빨강 ✕)
else if (FAIL > 0)          → '실패'   (serious, 주황 !)
else if (UNVERIFIABLE > 0)  → '주의'   (warning, 노랑 ?)
else                        → '정상'   (good, 초록 ✓)
```

색만으로 뜻을 전달하지 않습니다. **색 · 아이콘 · 글자** 세 가지를 함께 씁니다.

## 지표 이름

`load_metric_names()` 가 `metrics.yaml` 에서 `check_id → 한국어 이름` 매핑을 만듭니다.
yaml 에 없는 지표(원천 대비·채권·주식·현금 화면)는 **코드 안에서 회사별로 이름을 조립**합니다.

!!! bug "화면 이름표 하나가 낡았습니다"
    `cash_screen_*` 의 표시 이름이 「현금 화면 **3값** 정합성」으로 되어 있으나,
    실제로는 총 보유현금 · 통화별 합계 · 계열사별 합계 · 추이 그래프 **네 곳**을 대조합니다.
    이름표만 예전 것이고 검사 내용에는 이상이 없습니다.
    (`build_dashboard.py` 의 `load_metric_names()` 안에 문자열이 있습니다.)

## 공휴일 표시

`HOLIDAYS` 딕셔너리가 **파일 안에 연도별로 하드코딩**되어 있습니다.

```python
HOLIDAYS = {
    "2026-01-01": "신정",
    "2026-02-16": "설날 연휴", "2026-02-17": "설날", "2026-02-18": "설날 연휴",
    ...
    "2026-09-24": "추석 연휴", "2026-09-25": "추석", "2026-09-26": "추석 연휴",
    ...
}
```

- 일요일과 공휴일은 날짜를 붉게 칠하고, 공휴일은 이름을 함께 보여줍니다.
- **음력·대체공휴일은 매년 바뀌므로 해가 바뀌면 갱신해야 합니다.**
- 자금관리포털 쪽에는 자동 갱신되는 공휴일표가 따로 있습니다.
  값이 갈라지지 않게 하려면 나중에 그쪽을 참조하도록 바꾸는 편이 낫습니다(현재는 별도 관리).

## 갭 추세(스파크라인)

지표별로 `expected - actual` 을 시간순으로 그립니다.

- 가로선이 0 에 붙어 있으면 그 지표는 계속 정확했다는 뜻
- 「최근 갭 0 · 53회」 = 마지막 차이 0, 누적 검사 53회
- 검사 횟수가 지표마다 다른 것은 **지표가 추가된 시점이 다르기 때문**입니다
  (현금 화면 검사는 2026-08-21 이후라 19회)

## 실패해도 실행을 죽이지 않는다

`run_verification.sh` 에서 `|| true` 로 감싸 부릅니다.
대시보드 생성 실패가 검증 결과 자체를 잃게 만들면 안 되기 때문입니다.
(리포트 JSON 은 이미 저장된 뒤에 대시보드를 그립니다.)

## 팀원 공유용 사본 자동 발행 {: #share-copy }

생성된 `dashboard.html` 은 검증 PC 안의 파일이라 팀원이 열 수 없습니다. 그래서 같은 화면을
클라우드 문서로 한 벌 올려 두고 링크만 공유합니다. 그 사본은 스스로 갱신되지 않으므로,
검증이 끝나 대시보드가 새로 만들어질 때마다 다시 올립니다. 2026-09-22 부터 자동입니다.

| 단계 | 담당 | 하는 일 |
| --- | --- | --- |
| ① 올릴 파일 만들기 | `checks/build_share_copy.py` | 템플릿의 데이터 자리에 그날 결과를 끼워 넣어 `reports/dashboard_share.html` 생성 |
| ② 발행 | `checks/publish_share_copy.sh` | 배경 CLI 세션을 띄워 같은 주소에 다시 올림 (약 45초) |
| ③ 뒷정리 | `checks/share_session_cleanup.py` | 발행에 쓴 배경 세션 정리 — 이 폴더의 배경 세션만, 사람이 쓰는 대화형 세션은 건드리지 않음 |
| ④ 실패 알림 | `checks/share_alert.py` | 실패했을 때만 고정 문구 한 줄 (금액 미포함) |

**사본이 원본과 다른 점** — ① 문서 서비스가 스스로 씌우는 겉껍데기 태그 제거
② 색 토큰을 밝은/어두운 테마 3상태로 ③ 맨 위 「○○ 시점의 사본입니다」 안내 박스
④ 꼬리말에서 「자동 갱신됩니다」 문구 제거. 이 4가지는 `share/template.html` 에 이미
반영돼 있어 매번 다시 하지 않습니다. 날마다 바뀌는 것은 데이터 한 줄뿐입니다.

!!! warning "원본 화면이 바뀌면 발행이 스스로 멈춥니다"
    템플릿은 '그 시점의 원본'을 손본 것이라, 원본의 CSS·렌더 JS 가 바뀌면 사본만 옛 모습으로
    남습니다. 그래서 `build_share_copy.py` 가 원본 화면 코드의 지문(`share/fingerprint.txt`)을
    매번 대조하고, 다르면 **아무것도 올리지 않고 멈춥니다.** 달라진 걸 눈치채지 못한 채 옛 화면을
    계속 올리는 것이 가장 나쁘기 때문입니다.
    원본 화면을 고쳤다면 템플릿을 다시 만든 뒤 `--refresh-template` 로 지문을 갱신합니다.

!!! note "왜 배경 세션인가"
    무인 실행용 인쇄 모드(`-p`)에는 문서 발행 도구가 아예 없습니다(도구 목록에 없음).
    배경 세션 모드에는 있어서, 작업 스케줄러 → 셸 스크립트 → 배경 세션 경로로 발행합니다.
    세션 번호는 안내문 첫 줄이 아니라 `attach` 안내 줄에서 찾아야 합니다 — 배경 서비스가
    꺼져 있던 차례에는 다른 줄이 먼저 찍히기 때문입니다.
    결과는 화면 로그가 아니라 **결과 파일**로 주고받습니다(화면 로그는 색 코드가 섞여 불안정).
