# 운영과 인수인계

만든 사람이 없어도 굴러가게 하기 위한 문서입니다.
**이 페이지만 읽어도 하루·한 달·한 해 단위로 무엇을 해야 하는지** 알 수 있게 적었습니다.

## 매일 — 30초

대시보드(`reports\dashboard.html`)를 열어 오늘 칸만 봅니다.

| 보이는 것 | 하는 일 |
| --- | --- |
| 「정상」 | 없음 |
| 「주의」(검증불가) | 그냥 둡니다. 다음 실행 때 자동 정정됩니다. 3일 이상이면 [점검표](../manual/troubleshoot.md#64) |
| 「실패」·「위험」 | [대응 절차](../manual/troubleshoot.md#61-fail) 즉시 수행 |
| **칸이 비어 있음(평일인데)** | 검증이 안 돈 것입니다. PC·예약작업 확인 |

!!! danger "가장 위험한 상태는 '실패'가 아니라 '조용함'입니다"
    PC가 꺼져 있거나 예약작업이 멈추면 **아무 소리 없이** 검증이 중단됩니다.
    현재 이를 먼저 알려 주는 장치가 없으므로, 대시보드 맨 윗줄의
    「생성 (날짜 시각)」이 오늘인지 보는 습관이 유일한 방어선입니다.

## 값이 바뀔 때 — 자동

현금 값이 바뀌면 자동배포가 현금 검사만 다시 돌려 대시보드를 최신으로 유지합니다
([현금 재검증](recheck.md#cash)). 사람이 할 일은 없습니다.

## 해마다 한 번 — 공휴일표

`checks/build_dashboard.py` 안의 `HOLIDAYS` 는 **연도별로 손으로 적어 둔 것**입니다.
해가 바뀌면 갱신해야 달력의 빨간 날과 공휴일 이름이 맞습니다.

```python
HOLIDAYS = {
    "2026-01-01": "신정",
    ...
}
```

> 자금관리포털 쪽에는 자동 갱신되는 공휴일표가 따로 있습니다.
> 두 곳이 갈라지지 않게 하려면 나중에 그쪽을 참조하도록 바꾸는 편이 낫습니다(현재는 별도 관리).

## 담당자가 바뀔 때

1. [설치와 배포](deploy.md) 대로 환경을 확인합니다(같은 PC를 쓴다면 확인만).
2. `.env` 세 개 키의 소재를 인계합니다. **값은 문서가 아니라 사내 인수인계 자료로** 넘깁니다.
3. 아래를 한 번 돌려 지금 상태를 눈으로 확인합니다.
   ```bat
   cd /d <검증시스템 폴더>
   run_verification.cmd
   py docs\verify_manual_facts.py
   ```
4. 이 문서 사이트에서 [설계 원칙과 개발 규칙](conventions.md)을 읽습니다.
   **다섯 원칙을 깨는 변경은 되돌려야 합니다.**

## 미리 알아 두면 좋은 함정

여기 적힌 것은 전부 **실제로 한 번씩 겪은 일**입니다.

| 함정 | 무슨 일이 벌어지나 | 대비 |
| --- | --- | --- |
| **저장 데이터만 보는 검사** | 데이터는 멀쩡한데 화면 계산만 틀린 경우를 못 잡습니다 (2026-08-21) | 화면 코드를 실제로 실행해 비교 |
| **최신 1행만 보는 검사** | 과거 기준일에서만 나타나는 오류를 구조적으로 못 잡습니다 | 전 기준일을 훑기 |
| **사내 API 속도제한(429)** | 수집기와 시각이 겹치면 검증이 밀려 검증불가가 납니다 | 수집 09:00 / 검증 09:10 분리 + 호출 간격·재시도 |
| **화면 코드가 두 벌** | 배포본과 서버본 중 한쪽만 고치면 화면이 갈라집니다 | 현금 지문이 두 파일을 모두 해시 |
| **`.sh` 직접 더블클릭** | 경로에 공백이 있어 Windows 가 경로를 잘라 읽고 실패합니다 | 반드시 `.cmd` 로 실행 |
| **콘솔 한글 깨짐(cp949)** | 이모지·한글을 `print` 하면 프로그램이 죽습니다 | 판정은 ASCII 한 줄(`RESULT: ...`)로 주고받기 |
| **공휴일에도 실행됨** | 스케줄러에 공휴일 개념이 없습니다 | 정상 동작임을 알고 있을 것 ([4.5절](../manual/schedule.md#45)) |

## 아직 만들지 않은 것

| 갈래 | 상태 | 원래 계획 |
| --- | --- | --- |
| 보안 검사 | 폴더에 README만, 실행 목록에서 주석 처리 | 시크릿 노출·인증 우회·보안 헤더 |
| 파이프라인 검사 | 〃 | 신선도(갱신 지연)·이상치 급변 |
| 기능 검사 | 〃 | 화면 스모크 테스트 |
| 결과 알림 | 코드는 있으나 채널 미설정 | 실패·검증불가 시 자동 통보 |

지금 도는 검사는 **전부 수치(metrics) 갈래**입니다.
위 넷은 필요해지면 추가하되, [검사 항목 추가하기](extending.md)의 규칙을 따르십시오.

## 문서를 최신으로 유지하는 법

이 사이트의 내용이 실제와 어긋나면 문서가 오히려 사고를 만듭니다.
그래서 문서에 적은 사실을 프로그램이 다시 확인합니다.

```bat
py docs\verify_manual_facts.py          :: 26항목, 종료코드 0 = 전부 일치
py tools\check_public_safe.py           :: 공개하면 안 되는 정보가 섞였는지
```

문서를 고치면 **확인 프로그램도 함께** 고치십시오. → [문서 자가 검증](self-check.md)
