## 2026-09-04 · 현금 재검증 (`cash_recheck.py`)

**무엇이 문제였나** — 전체 검증은 하루 한 번(09:10)인데 현금 데이터는 낮·저녁에 회사별로 따로
들어옵니다. 09:10 에는 3사가 모두 전일 이월이라 멀쩡했다가, 한 회사만 당일 마감이 끝나면
계열 화면이 3사 합과 어긋났습니다. **「경고 창은 떴는데 현황판은 멀쩡」** 한 상태가 됐습니다.

**대책** — 자동배포가 매시간 스냅샷을 만들 때 **현금 지문**을 비교해, 값이 실제로 바뀌었으면
현금 검사 7건만 다시 돌리고 그날 리포트·대시보드를 갱신합니다.
지문이 같으면 아무것도 하지 않아 하루 스무 번 넘게 불려도 헛돌지 않습니다.

→ [사후 재검증과 현금 재검증](dev/recheck.md#cash)

## 2026-08-31 · 채권 매입금액 — 통화별 비교로 전환

**무엇이 문제였나**

1. **이름과 숫자가 달랐다** — 지표명은 「채권 매입금액·경과이자」인데 기대값/실측값은 매입금액만의 합이었습니다.
2. **통화를 섞어 더했다** — KRW·USD·JPY 원금액을 환산 없이 합산했습니다. 그 결과 화면에 찍힌 값이
   실제 규모의 **9분의 1**에 그쳤습니다. 통과/실패 판정은 맞게 나오지만 **금액으로 읽는 순간 오독**합니다.

**왜 '원화환산'이 아니라 '통화별 비교'인가** — 매입금액은 이미 확정된 **취득원가**입니다.
환율로 환산하면 산 값이 변하지도 않았는데 매일 숫자가 흔들려, 무엇이 달라진 것인지 읽기 어려워집니다.
원천도 통화별 원금액으로 들고 있으므로 같은 자로 나눠 비교합니다.

**결과** — 지표가 `bond_purchase_{회사}_{통화}` 로 쪼개졌습니다.
어느 통화가 어긋났는지 화면에서 바로 보입니다.

## 2026-08-28 · 검증불가 사후 재검증 (`recheck.py`)

**무엇이 문제였나** — 2026-08-13 09:00 검증에서 장금상선 채권 3항목이 검증불가로 남았습니다.

```
metrics.bond_purchase_sinokor   UNVERIFIABLE
metrics.bond_price_sinokor      UNVERIFIABLE
metrics.bond_holdings_sinokor   UNVERIFIABLE
  검증 불가: SamsApi HTTP 429 /api/v1/fa/falist
  {"success":false,"errorCode":"RATE_LIMITED","message":"요청이 너무 잦습니다..."}
```

원인은 **사내 API 속도제한**이었습니다. 그날 수집기와 검증기가 같은 09:00 에 같은 API 키로
호출했고, 회사 순서대로 조회하다 장금상선 차례에서 한도에 걸렸습니다.

**대책** — 그날 저장된 포털 스냅샷 + 그날 기준일로 다시 부른 원천으로 **그날의 검증을 재현**해
과거 리포트를 정정합니다. 정정 사실은 숨기지 않고 ↺ 표시로 남깁니다.

→ [사후 재검증](dev/recheck.md)

## 2026-08-21 · 현금 화면 검증 추가 + 속도제한 대응

이 시스템의 **형태를 결정한 날**입니다.

**장애** — 자금관리포털 현금 화면의 「총 보유현금」과 「계열사별 보유현금」이
**과거 기준일에서만** 어긋났습니다. 차이는 백억 원 단위까지 벌어졌습니다.
①상단·②통화별은 최신일 환율로, ③계열사별·④추이 그래프는 그 날 환율로 환산하고 있었습니다.

**기존 33개 검사가 못 잡은 이유**

1. **저장 데이터만 봤다** — 데이터는 멀쩡했고 '화면 계산'만 틀렸습니다.
   내부 정합성 검사(`branch_totals` · `cash_bycur`)는 통과할 수밖에 없었습니다.
2. **최신 1행만 봤다** — 기존 지표는 모두 `order=...desc&limit=1` 이었습니다.
   과거 기준일에서만 나타나는 결함은 **구조적으로 검출 불가**였습니다.

**대책** — `cash_screen.py` 신설. 화면 코드를 node 로 **실제 실행**하고 **전 기준일**을 훑습니다.
아울러 `common/samsapi.py` 에 호출 간격(0.35초)과 재시도(1.5s → 4.0s)를 넣고,
실행 시각을 수집 09:00 / 검증 09:10 으로 분리했습니다.

→ [구조와 데이터 흐름](dev/architecture.md) · [검사 프로그램 5종](dev/modules.md)
